# Local SaaS role-flow validation - 24 October 2026

Executed locally with separate role agents and isolated browser sessions.
The synthetic service ran on loopback port 8007 with its own disposable PostgreSQL
database and temporary recording directory. The real application database on port
8006 was not seeded with test users. No VPS access or deployment occurred.

## Issue found and fixed

Malformed saved layouts previously returned HTTP 500 with a generic server error.
The SaaS preference handler now returns HTTP 400 / `invalid-preferences` and
preserves existing saved settings. Regression checks cover invalid layout grid,
wrong camera count and invalid favourites. Windows v2 source was unchanged.

## Limits

### Follow-up: manual superadmin password support

Added superadmin-only workspace user lists and temporary-password reset for
admins and members. Seven additional automated checks verify authorization,
weak-password rejection, session revocation, forced password change, unchanged
provider credentials, unchanged pending/suspended status and sanitized auditing.
Ordinary admins and members cannot call the platform reset endpoint. It cannot
reset the superadmin account through the workspace recovery path.

Isolated headless Chrome also verified the real superadmin UI for both member
and admin reset, password-confirmation mismatch handling, cleared password
inputs, invalidated old sessions, mandatory next-login password change and
390px layout with no overflow or script errors. The existing Chrome DevTools
connection was unavailable; this check used a separate temporary browser profile.
Disposable PostgreSQL users/data were used. Email verification and email-based
recovery are excluded at the user's request; the owner provides direct support.

### Remaining validation limits

Health follow-up: 13 checks cover root-only reads/scans/actions, RLS denial,
stream detection/deduplication/recovery, acknowledgment, storage thresholds and
probe failures, server errors, persistence and bounded fallback. Browser checks
passed root-only navigation, actions, filters, metrics, stale-data signaling,
refresh recovery and 390px layout. Signals were synthetic. Workspace quotas were
not implemented; see HEALTH-MONITORING.md.

Audit follow-up: nine additional checks passed for role/workspace scope, metadata
redaction, filters, cursor pagination, manual deletion, retention cleanup, blocked
cleanup when the intent cannot be audited and denied UPDATE/DELETE of history.
Headless Chrome verified platform/admin/member navigation, filters, older pages,
details, escaped target text, deletion events and 390px layout with no unexpected
script errors. Details and outcome semantics are in AUDIT-LOG.md.

Follow-up account recovery adds encrypted opt-in web reauthentication, database
leases/backoff, background discovery and revocation checks, verified updated-iVMS
credential recovery, stale-result protection and same-account camera restoration.
PostgreSQL fault tests cover these paths; headless Chrome verifies opt-in,
expiry feedback, restored camera arrangement, preserved manual stops, disabling
saved sign-in and the 390px layout. No unexpected browser script errors occurred.
The detailed controls and remaining real-account/SDK acceptance gate are in
ACCOUNT-RECOVERY.md. These additions do not establish independent SDK-token
minting or a verified personal-account refresh-token endpoint.

These results validate the local application workflow and authorization model;
they do not establish actual Hikvision camera availability, production security
certification or unattended provider renewal. Provider calls and live images in
the fixture are synthetic. Its live generator emits JPEG and silent audio, not
H.264 packets; Smooth mode and real microphone/audio quality were not validated
by these role tests. Clip playback used a separately generated valid WebM.

Physical-camera soak, network interruption, operating-system/server restarts and
independent SDK reauthorization remain pending. Reopening a database pool or
recording store is not a full operating-system restart test. Continue the saved
reliability checklist when cameras are online. Historical recorder-footage
playback remains on hold as requested; tested clips are viewer-created recordings.

HTTPS/domain and production rollout remain deferred. Local v3 is available on
http://localhost:8006/; the VPS was unchanged.
